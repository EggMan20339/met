# Animating Glimmerdeep's characters

Every character, creature, boss, friend, prop and pickup is a **live vector puppet**: its art template
(`tools/art/**.js`) is a pure function of a parameter object, and every frame the game calls it with
parameters that have been tweened toward targets chosen from the game state. Nothing is a sprite sheet.
Ears lag, tails trail, jaws open continuously, squash and stretch overshoot and settle. The reference
implementation is `tools/art/mote.js`; read it first, then this.

## The pieces

| Piece | What it does |
| --- | --- |
| `tools/art/lib.js` | Drawing helpers that return scene ops (`path`, `ell`, `circ`, `rect`, `stroke`, `line`, `g`, `glow`, `eye`, `glowEye`, `curve`, gradients `lin`/`rad`, transforms `rot`/`tr`, `mix`/`shade`/`lerp`/`clamp`, `rng`). `svg(w, h, ops)` makes a scene; `toSvg(scene)` serialises it for `art/*.svg`. |
| `src/vec.js` | `Vec.draw(ctx, scene, x, y, {anchor, scale, flip, sx, sy, rot, alpha})` paints a scene onto the game canvas. Paths and gradients are cached, so static shapes are nearly free; shapes whose numbers change every frame cost a little more. |
| `src/puppet.js` | `Puppet` (parameters, targets, springs, chains, ghosts), `Chain` (verlet rope), `Anim.keys` (keyframes), `Anim.spring`, `Ease.*`, `puppetFor()`. |
| `src/artsrc.js` | Generated by `node tools/bundle-src.js`: every module in `tools/art/index.js` wrapped for the browser as `ARTSRC.<basename>`. |
| `src/sprites.js` | Finds the module for an entity (`PUPPET_OF`), calls `control`, `update` and `draw` (`livePuppet`). You do not edit it to add a character. |
| `tools/filmstrip.js` | Captures a strip of frames of one subject in the running game. Your eyes for this work. |

## Module contract

```js
const L = require('../lib');                       // '../lib' from a subfolder, './lib' from tools/art/
const { svg, path, ell, circ, stroke, g, rot, tr, glowEye, glow, curve, lin, rad, mix, clamp } = L;
const W = 26, H = 20;
const params = { legPhase: 0, legLift: 0, headTilt: 0, headTurn: 0, bob: 0, sx: 1, sy: 1, eye: 1, glowK: 1 };   // every tweened value, at rest
const springs = { headTilt: [300, 0.5], sx: [420, 0.5], sy: [420, 0.5], bob: [260, 0.6] };                      // [stiffness, damping ratio]
const poses = { a: {}, b: { legPhase: Math.PI } };                                                           // stills: art/<name>_<pose>.svg
function make(P, pup) { /* pure: parameters in, scene out; pup (may be undefined) only for chain points */ return svg(W, H, [ ...ops ]); }
function control(ent, pup, info) { /* game state in, pup.target({...}) / impulses / chains out */ }
module.exports = { name: 'dimling', w: W, h: H, anchor: 'bottom', params, springs, poses, make, control };
```

- `name` is the registry key and the `ART_SCALE` family (`src/art.js`), which sets world units per template unit.
  Export `scale` (a number, or `(ent) => number`) to override, e.g. a pickups module that draws several kinds.
- `anchor` is `'bottom'` (feet at the hitbox bottom, x centred) for anything that stands, `'center'` for fliers,
  bosses that hover, pickups. `w`/`h` are the template's box; draw inside it (shapes may poke out a little).
- **Everything faces right.** The game flips the whole scene when the entity faces left (gradients flip with it).
  Export `flip(ent, pup)` only if your module needs a different rule (Mote's cling pose keeps its wall on the left).
- `params` must list every value `make` reads, with its rest value. Numbers with a `springs` entry ease toward their
  target with overshoot; numbers without one, and strings/arrays, apply at the next update. Use strings for modes
  (`pawKind: 'strike'`) and springs for anything that moves.
- `poses` are the stills exported to `art/` by `node tools/make-art.js` and shown on `tools/art-sheet.html`. Keep the
  ones that existed for your subject (same names) and add any new readable pose. A pose named `default` exports as
  `art/<name>.svg` (use it for subjects that had a single still, like `bramble`).
- `make` must be deterministic and allocation-light: build the ops array, no `Math.random()`, no big precomputation
  per call; precompute constants at module load. Keep it under ~60 ops. Read chains through `pup` only if present
  (`pup && pup.chains.tail ? pup.chains.tail.points() : restPoints`), because the stills are made without a puppet.
- `control(ent, pup, info)` runs once per rendered frame, before `pup.update(info.dt)`. `info` has `dt` (seconds, 0
  while paused, scaled by slow motion and hit-stop) and `t` (game time); decor also gets `game`, `lit`, `active`,
  `glowAt(x, y, r, color, alpha)`; puffcap tiles get `game`. Keep per-entity memory in `pup.mem` (timers, previous
  values for event detection, random choices). `pup.time` is the puppet's own clock.
- Optional `before(ctx, ent, pup, info)` / `after(ctx, ent, pup, info)` draw world-space effects under or over the
  body (trails, telegraph glows, lantern light). The context is in world units at the entity's position already
  transformed by the game; do not change the entity.
- A module may also export `stills: { name: { w, h, anchor, make } }` instead of a character, for static art.

## Puppet API (src/puppet.js)

- `pup.target({ k: v, ... })` set targets; `pup.snap({...})` set now; `pup.impulse('sy', -3)` kick a spring value's
  velocity (per second): landing squash, recoil, a flinch, an ear flick.
- `pup.chain('tail', ax, ay, [{x, y}, ...])` get or create a verlet rope anchored at template point (ax, ay) with
  those rest offsets; `chain.update(dt, { vx, vy, facing, gravity, drag, stiff, damp, wind })` with the owner's
  world velocity converted to template units (`vx / scale`); `chain.points()` gives `[anchor, ...points]` for
  `curve()`. Ropes stream behind movement, hang under gravity and settle to their rest pose.
- `pup.ghost(x, y, life, alpha)` remembers the pose at a world position; the game draws ghosts fading (dash trails).
- `Anim.keys(k, [[0, {...}], [0.3, {...}, 'outCubic'], [1, {...}]])` samples keyframes at `k`; `Anim.wave(ph, lo, hi)`;
  `Anim.smooth(v, a, b)`; `Ease.outBack`, `Ease.outElastic`, `Ease.inOutCubic`...

## What the game gives you

Enemies (`src/entities.js`, `updateEnemy`): `state` (per type: idle/walk/hurt, tele/lunge, charge, stun, shell, fire,
wait/air/land, swing_tele/swing/lunge_tele/lunge/stagger...), `t` seconds in state, `vx`/`vy`, `facing`, `anim`
(a free-running clock), `aggro`, `hp`/`def.hp`, `flash` (> 0 right after a hit), `events` (strings pushed this tick:
`alert`, `lunge`, `charge`, `bonk`, `spit`, `hop`, `land`, `swing_tele`, `swing`, `lunge_tele`, `stagger`, `blocked`).
Detect your own events by comparing with `pup.mem` (previous state, previous hp) rather than relying on `events` alone.
Bosses (`updateLightless`, `updateGulletroot`, `updateBell`): `state`, `t`, `phase`, `vulnerable`, `floorY`, `arena`,
`spots`, `alive`/`deathT`. Friends and props are static entities (`tx`, `ty`, `type`); their motion is all yours.
Pickups: `type` (`H` petal, `S` heartwood, `1`..`4` gifts, `*` the heart), `x`, `y`, `t` (a per-pickup phase).
The player (`src/player.js`): see mote.js.

## The quality bar

A module is done when all of this is true, and visible on its filmstrips:

1. **Idle life.** Nothing ever holds still: breathing, a sway, a flicker, a blink, an occasional fidget on a random
   timer (`pup.mem`). Fliers hover on a slow figure-eight. Glowing parts pulse.
2. **Locomotion tied to speed.** Legs, wings or body cycle at a rate from `vx`/`vy` (`e.anim` is not speed); the body
   bobs and leans with it; stop and start with weight (lean into acceleration, overshoot on stops).
3. **Anticipation, action, recovery** for every attack and special state: wind up (compress, pull back, glow builds)
   for the telegraph, snap on the hit frame (an `impulse`), settle with overshoot. Readable at a glance: a player
   should know what is coming from the pose alone.
4. **Reactions.** A flinch when hit (`flash > 0` or hp dropped), a stagger/stun that looks dazed (eyes, droop),
   a shell/guard that looks closed, a death that is not a pop (the game fades it; give it a last twitch if you can).
5. **Secondary motion.** Appendages lag the body: antennae, tails, tentacles, cloth, lantern poles on springs or
   chains; ears flop on landing; glows swell after the body moves.
6. **Eyes.** Blink, look toward the player when aggro, go wide on alert, shut or spin on stun.
7. **Shape integrity.** No part detaches, no limb passes through the body, no flicker between frames; silhouettes
   match the original stills so the creature stays recognisable. Hitboxes do not change.
8. **Cost.** Under ~60 ops, no allocation storms; the game runs ten of you on screen.

Use real timing: the attack hit frame must line up with the game's own timers (`e.t` thresholds in `updateEnemy`),
not with a clock of your own.

## Verify

```
node --check tools/art/creatures/rootram.js
node tools/make-art.js --check creatures/rootram --out /tmp/rootram-stills     # stills export without errors
node tools/bundle-src.js --out /tmp/artsrc-rootram.js                          # a private browser bundle
node tools/filmstrip.js --artsrc /tmp/artsrc-rootram.js --subject enemy:c --frames 16 --every 3 --out /tmp/rootram-idle.png
node tools/filmstrip.js --artsrc /tmp/artsrc-rootram.js --subject enemy:c --set '{"state":"tele","t":0}' --frames 20 --every 2 --out /tmp/rootram-charge.png
node tools/filmstrip.js --artsrc /tmp/artsrc-rootram.js --subject enemy:c --poke --frames 12 --every 2 --out /tmp/rootram-hit.png
```

Look at every strip (the Read tool shows PNGs). Subjects: `player`, `enemy:<type letter>`, `boss:<kind>`,
`decor:<type char>` (B hearth, T lamp, + crystal, N Wick, W Bramble, Q Tallow, K Bell Ringer), `pickup:<type>`.
Set `PW_MODULE` to the playwright install if it is not in node_modules. Only the shared generated files
(`src/artsrc.js`, `art/`) are written by the plain commands; use `--out`/`--artsrc` while iterating.
